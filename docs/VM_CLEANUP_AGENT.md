# Завершение аренды через VM-агент

Бот больше не пытается автоматизировать сайт Steam. При окончании аренды он вызывает приватный HTTP-агент, который управляет Windows-VM, где запущен Steam. До подтверждённого ответа агента аккаунт остаётся со статусом `rented`.

## Подготовка базы и бота

Перед выкладкой один раз выполните:

```bash
node --env-file=.env scripts/addRentalCleanupLifecycle.js
```

Затем задайте в `.env` адрес контроллера VM в приватной сети и длинный случайный токен:

```env
RENTAL_VM_AGENT_URL=http://10.10.0.15:8787
RENTAL_VM_AGENT_TOKEN=<at-least-32-random-bytes>
RENTAL_VM_AGENT_TIMEOUT_MS=45000
RENTAL_RENEWAL_GRACE_MS=120000
RENTAL_CLEANUP_RETRY_INITIAL_MS=30000
RENTAL_CLEANUP_RETRY_MAX_MS=3600000
RENTAL_CLEANUP_LEASE_MS=75000
```

Не публикуйте этот HTTP-порт в интернете. Разместите его в Tailscale/WireGuard/VPN или закройте firewall так, чтобы к нему мог подключаться только бот. Токен передаётся в `Authorization: Bearer …`; храните его в секретах окружения, не в Git и не в базе.

## Контракт агента

Бот вызывает:

```http
POST /v1/rentals/{rentalId}/cleanup
Authorization: Bearer <token>
Content-Type: application/json

{"rentalId":123,"accountId":45,"attempt":1}
```

Пароль Steam, cookies и `maFile` в запросе не передаются. Успех допустим только после фактической проверки:

```json
{"ok":true,"stoppedSessions":1,"steamProcessesRemaining":0}
```

При любой ошибке возвращайте non-2xx или `{ "ok": false, "reason": "..." }`. Бот оставит аккаунт занятым и выполнит повтор с экспоненциальной задержкой до одного часа.

## Действия внутри Windows VM

Агент должен быть идемпотентным: повтор одного и того же `rentalId` должен быть безопасен.

1. По `accountId` определить закреплённую за аккаунтом VM и временного Windows-пользователя арендатора.
2. Заблокировать новые подключения этого пользователя.
3. Завершить его RDP/Parsec/Moonlight-сессию.
4. Завершить Steam и процессы игры именно в этой VM/профиле.
5. Удалить временный Windows-профиль либо откатить VM-снапшот.
6. Проверить, что сессии и процессы отсутствуют, и только затем вернуть `ok: true`.

Если каждому Steam-аккаунту выделена отдельная VM, контроллер может маршрутизировать `accountId` на нужную VM. Не используйте один общий `taskkill Steam.exe` на хосте с несколькими арендаторами: это завершит чужие аренды.

## Продление и автопродление

`extendActiveRental` блокирует строку аренды и продлевает от `max(ends_at, NOW())`, поэтому оплата, пришедшая чуть позже срока, не теряет уже прошедшее время. После старта очистки продление намеренно отклоняется: аккаунт уже не может быть выдан повторно.

Есть два места для будущего автопродления:

- `RENTAL_RENEWAL_GRACE_MS` — окно перед очисткой, в котором обработчик оплаченного продления успевает вызвать существующий `extendActiveRental`;
- `renewalResolver` при создании `createExpiryChecker` — доверенный callback. Он возвращает `{ hours, reason }`, чтобы продлить аренду до вызова VM-агента, или `null`, чтобы завершить её.

Например, интеграция рекуррентного платежа может искать в своей таблице подтверждённое продление и вернуть `{ hours: 24, reason: 'subscription:<id>' }`. Не выполняйте внешний платёжный запрос внутри callback без идемпотентного ключа: воркер может запуститься повторно.
